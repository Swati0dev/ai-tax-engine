## Phase Rules

- Follow phases in order unless a documented decision changes the sequence.
- Each phase must have clear objectives, tasks, and deliverables.
- Each task must be logged in `docs/logs/LOG.md` before execution.
- Meaningful lessons must be recorded in `docs/logs/IMPROVEMENTS.md`.
- Do not start coding until the relevant planning and workflow files have been reviewed.
- Do not move to implementation unless Phase 1 validation confirms the relevant architecture, workflow, source, and safety rules are documented.
- Treat tax-content work as blocked unless research, content, and validation workflows are clear for the content being changed.
